# BIT 对照下的单树有限预算差距

## 范围与证据口径

本文件解释当前单树为何在有限预算下未稳定转化更多搜索为更短目标路径。结论按已有基准、表示诊断和源码机制分层；没有通过消融隔离各因素，因此以下是有证据支撑的机制诊断，不是单一因果归因。

观察路径质量时须分开记录首解和后续改进；首解较差不等于算法后续不能持续改善。不同预算和安全设置下的指标不作直接速度排名。

BIT* 的核心参考为 [Batch Informed Trees](https://arxiv.org/abs/1405.5848)：其将采样描述的隐式随机几何图按启发式顺序搜索，并跨批次复用搜索信息。此处只比较项目中的 BIT 实现与单树，不将论文的理论保证自动转移到证书规划问题。

## BIT 基准结果

项目外部基线在 forest、dense、slots 各使用 50 个 seed（0–49），以 10 s 在线时间为预算；checkpoint 的路径提取和 shortcut 不计入在线时间。BIT 批大小选为 200。记录中的 `raw` 是原始树路径，`L` 是 shortcut 后长度。

| 场景 | BIT 成功率 | 当前 raw | shortcut 后长度 | 首解在线时间/s |
|---|---:|---:|---:|---:|
| forest | 50/50 | 14.0077 | 14.0047 | 1.112 |
| dense | 50/50 | 18.6787 | 18.6026 | 0.088 |
| slots | 50/50 | 13.3288 | 13.2569 | 0.370 |

BIT 的 raw 树路径本身也在首解后明显改善：forest 首解到末次 raw 中位数为 20.377 → 14.008，逐运行首解后改善中位数 31.199%；dense 为 20.219 → 18.679、改善 7.869%；slots 为 15.163 → 13.329、改善 12.147%。末次树 `vertices` 中位数分别为 1306、3361.5、2237.5。这里改善率是逐运行计算再取中位数；首末 raw 中位数之差仅作描述。该证据说明 BIT 的持续改善并非仅来自 shortcut，也不能简单归结为产生更多树顶点。

相对历史 A 在约 2.866 s 在线预算下，forest 的 BIT shortcut 路径逐 seed 中位数仍差 2.823%；到 10 s 时则好 10.432%。因此不能概括为 BIT 在所有时间点都优于 A。这里历史 A 使用 `step=0.6`，不等于当前 `step=0.3` 的 A；这些时间点也不是与当前证书单树的同安全、同预算、同方法比较。

安全口径也需分开：外部基线按机器人半径及地图 margin 之外再留 0.04 clearance，边检查分辨率为 0.02；证书版本使用自己的连续证书及额外 0.02 物理安全间隙。两套结果不能说成完全匹配的可行域和预算比较。

## 区域表示不是首要已证瓶颈

`results/bit_cell_coverage/runs.jsonl` 保存 20-seed 区域表示诊断。在 forest 的 spacing 0.25 设置中，沿 BIT shortcut 路径构造的证书全部有效（20/20），且满足额外 portal overlap；采样位置覆盖率为 1。相同路径序列的 chain 代价相对 BIT 的配对中位差为 +0.0040928%。

这说明在该诊断设置里，现有区域构造能表达一条接近 BIT 的路径，因而“必须整体移除区域表示或额外 portal 余量才能得到该路径”不是主要已证解释。此结果只适用于这些地图、路径及 spacing 参数，不证明任意区域集合都能表达任意路径。

原 A 树自身区域对 BIT 路径的几何覆盖率中位数为 0.709777；在相同位置替换为 BIT 最近 yaw 后为 0.997914。后一个替换是诊断手段，不是可直接部署的路径构造；它显示姿态/anchor 表示也会影响覆盖指标，不能把 coverage 差异单独当成可行性或路径质量结论。

## 算法将预算花在哪里

项目 BIT 实现在 `formation/baselines.py`。获得 incumbent 后，它从受 $\hat g(x)+\hat h(x)<c_{best}$ 限制的 informed set 生成新 batch；每批保留有效但尚未接入树的 samples。`q_v` 按 $g(v)+\hat h(v)$ 排序展开顶点，`q_e` 按 $g(u)+\hat c(u,v)+\hat h(v)$ 排序候选边，并在需要时才执行边有效性检查。新 batch 重建队列时复用已有树及仍存活的未连接样本。

因此 BIT 的优势机制不只是某个样本的父节点选得更好：启发式同时影响 incumbent 后的采样区域、先展开哪些顶点、先尝试哪些边，以及失败或尚未尝试的状态是否跨轮保留。它是对隐式图的启发式搜索，不是 GCS 求解，也不是每一步运行全图 Dijkstra。

BIT 的 informed 剪枝使用可采纳下界 $\hat g(x)+\hat h(x)$：当它不小于 incumbent $c_{best}$ 时，才可将未接入样本排除在当前改进集合外。当前树上的 $g(x)$ 是一条已知可行父链的代价上界，不能替代全局下界并据此永久删除仍可能改进的样本。

当前讨论版本是 `CertificateRadiusTree`，见 `formation/certificate_radius_tree.py`。它持续做全域 uniform/goal-bias 采样，不按 incumbent 收缩到 informed set，也没有全局的 $g+\hat h$ 顶点/边优先队列。对一个固定新目标点 $q$，不同父节点候选的 $\hat h(q)$ 相同；在父节点之间比较 $g(u)+d(u,q)+\hat h(q)$ 与比较 $g(u)+d(u,q)$ 完全同序，所以单独把 $\hat h(q)$ 加到 ChooseParent 排序并不会改变选择。启发式只有用于不同目标状态或边的跨候选排序、采样限制和搜索调度时，才会改变计算优先级。

`CertificateRadiusTree.step` 先尝试把覆盖样本或近邻 uniform 样本直接以 $q$ 为 anchor 插入；若直接插入失败且该分支没有因无效证书提前返回，会再以同一个 $q$ 驱动区域扩展和 witness 插入。直接插入与后续扩展均失败时，或扩展 `_steer` 失败时，$q$ 不作为未连接树状态保留。它会保存尝试中产生的局部证书缓存，但这不等于保存未连接状态并在新 batch 中公平重考虑。相比之下，BIT 的有效未接入样本可继续留在隐式候选图中，之后随树和队列变化重新产生连接机会。

这支持“当前预算较多地用于无 incumbent 引导的空间覆盖与逐状态连接尝试，较少用于按有希望的 start-to-goal 下界排序”的机制判断；没有已有消融量化每一项贡献，故不把它定为唯一原因。

## 连接尺度与有效样本数

`CertificateRadiusTree` 取 $\gamma=1.5$，沿用了旧半径尺度，没有依据有效采样密度或目标路径误差校准。其 6000 次 attempt 时半径为 0.5027039。此前推导的收缩半径充分条件依赖有效密度 $\kappa_n$；理论上允许某个正 $\gamma$ 并不意味着 6000 次时该数值已提供足够有效边。

项目 BIT 的 3D 半径系数为

$$\gamma_{BIT}=2\,s_{rewire}\,\left(1+\frac13\right)^{1/3}
\left(\frac{V_w}{4\pi/3}\right)^{1/3},$$

其中本项目配置的重连系数 $s_{rewire}=1.1$，$V_w=\operatorname{area}(Q_{xy})\,2\pi\rho$。BIT 使用存活有效样本数 `count` 更新

$$r=\gamma_{BIT}\left(\frac{\log(\text{count})}{\text{count}}\right)^{1/3},$$

不对该半径施加 RRT 的 step cap。这里的 count 不是主循环 raw attempts，也不是证书数。

只构造当前场景的 BIT 对象读取其 $\gamma$（不运行规划），得到 forest 13.4061、dense 12.1802、slots 13.6718。把同一系数形式代入数值 count=6000，几何半径分别是 1.5173、1.3786、1.5474。这只是半径公式量级对照，不是历史 BIT run 的末时半径；实际 alive count 未保存，且 BIT 与单树的计数语义、连接模型不同。

因此不能只比较指数 $1/3$ 与理论的 $1/(d+1)$，也不能把 BIT 的 $\gamma$ 直接搬给单树。半径必须和参考路径上的有效样本密度、有效连接概率、度量体积、连接代价及目标精度一同校准。增加半径会扩大几何候选集合，但不保证更多候选通过证书认证，也会增加连接开销。

## 新版数据与“算得多但改进少”

证书连接缩半径版本在 6000 attempts 后，首解后 raw 改善中位数为 forest 1.135%、dense 0.1997%、slots 1.038%。节点数中位数约为 3319、3648.5、4118；证书数中位数约为 6115、4080.5、1575.5。累积大量状态和证书没有稳定转换为目标路径代价下降。

该观察与“只要修正子树 $g$ 传播”或“只要增加快速证书查询”不足以解释全部差距相符：已有统计中代价传播很小，局部连接调用和候选处理仍有成本。不过节点、证书数与代价改进不是因果识别实验，不能据此断言哪一项必然浪费或哪一项主导退化。

半径差距也不宜孤立看待。若抽到的状态大多远离有希望的完整路径，或候选局部连接不能及时完成认证，那么更宽近邻仅增加候选和认证负担；若有效状态密度不足，收缩半径又可能切断参考链邻接。当前 `CertificateRadiusTree` 已取消上一版 `SingleTreeRRTStar` 的 exclusive-owner 跨边限制；不能把上一版的限制当作当前版本效率不足的原因。两版的差异必须按实现版本区分。

## 诊断结论与设计原则

目前有证据支持的解释是：BIT 能把有限预算定向到 incumbent 相关状态和较低下界的连接，并保留未接入候选；当前 `CertificateRadiusTree` 的采样、状态固定和连接尺度尚未配套提供同等强度的有用状态密度与跨候选搜索排序。上一版 `SingleTreeRRTStar` 的 exclusive-owner 跨边限制属于已被当前版本消除的因素，不与当前版本的采样及调度不足混为一谈。区域表示诊断表明至少在 forest 的指定路径上，既有证书可表达接近 BIT 的链，因此不应把删除区域或放宽安全余量当作首要已证修复。

后续设计目标应是让有限预算内有希望的完整路径候选获得足够的状态采样与边尝试机会：区域扩展和路径状态生成可由可采纳 start-to-goal 下界协调；连接尺度按有效密度、度量体积、attempt 计数口径与目标精度设计；早期尚未接入但仍有潜力的样本应有明确保留或再考虑规则。

这些原则不要求照搬 BIT，也不要求回到 A。当前证据没有通过消融比较这些机制的单独效果；本文件不提出立即实现某个队列或参数，也不把 BIT 结果当作同安全、同预算的直接优越性证明。
