# 增量稀疏认证树（ISCT）v0.1 实现草案

> 工作名，不作新颖性声称。本文是首版实现规格；几何推导见[区域树渐进细化推导](区域树渐进细化推导.md)与[稀疏认证状态树算法推导](稀疏认证状态树算法推导.md)。

## 1. 目标与范围

ISCT 将区域发现、固定认证状态细化和路径优化放入同一长期循环。一个 cell 可有多个状态与门户，不假设“一大区域唯一入口”。区域发现 recipe 与活跃路径 parent 分离：前者保存新区域的可行到达证据，后者是已发布状态图上的单父树。

状态图保留稀疏候选边，按单调增加/降权的边批次增量维护 SSSP。它不是 GCS，也不在每轮从头全图 Dijkstra。算法输出单父可行路线；坏树不触发独立补救阶段。

## 2. 证书与端点

固定 $\rho$，单证书 chart 坐标为 $z=(x,y,\rho\theta)$。cell $i$ 有凸证书集 $C_i$ 与严格域

$$
D_i=\{z\in C_i:\operatorname{slack}_i(z)\ge\delta\},\qquad \delta=0.02.
$$

沿用当前 $\delta$。普通状态属于其全部证书 $D_i$；普通边两端共享证书，使用该证书 chart 的欧氏长度。因凸性，两端通过 slack membership 后线段有证书保证，不逐边运行碰撞采样、LP 或 SOCP。canonical yaw 只用于精确物理 intern；边保留选定证书 chart 的展开 yaw 增量。当前 cell 构造限制 $0<\text{yaw\_chart}\le\pi/2$，单 cell lift 唯一。

owner feature 网固定用 owner cell chart；portal pair $(i,j)$ 网固定用较小 `cell_id` 的 chart lift。pair 状态必须同时通过两侧 $D$ membership。feature 内距离与 packing 始终使用其固定 chart，不随查询改 lift。

source 是独立 endpoint 身份，不是 $D_i$ 普通状态。若 $C_i$ 含起点且起点 slack $\ge0$，cell 为 `startCapable`；每个该证书状态都有不受 $r$ 限制的 $s\to v$ 端点星边。起点可在 $C_i$ 而不在 $D_i$；此例外不适用于门户。

自由 yaw 目标用虚拟 sink $G$，无出边。每状态/goal-capable 证书最多一次调用 `RegionGeometry.goal_yaw(cell, goal_xy, v.yaw, delta)`，缓存可行区间/无解；合法时建立不受 $r$ 限制的 $v\to G$ 边。目标仍满足该接口的严格余量。根状态可直接尝试 $s\to G$，不等采样命中零测度 yaw。

## 3. 数据与不变量

- `Cell`: `id,C,D,seed,startCapable,discovery_parent,discovery_anchor,portal_anchor,spatialBounds,goalYawInterval`。
- discovery recipe 为持久链 `PathRecord(prefix_ref, immutable_edge, total_cost)`；扩展共享 prefix，仅每 cell 增加 $O(1)$ 记录，不复制整条历史路线。
- `Feature`: 固定身份，owner cell 或 portal pair；独立 ordinary $h$ 网，pair 可有至多一个强制 anchor；不维护全量成员模式，不因新 cell 重分类旧点。
- `Vertex`: 精确 canonical pose intern，坐标固定；feature/cert membership 只增加。epsilon 近点不合并。每新 cert membership 缓存 cert version、chart、slack 结果。
- `Edge`: 不可变 `{u,v,weight,cert_id,chart,witness,birthbatch,version}`。相同端点更短边建新 payload；active 最小索引在批次发布时更新。旧 payload 被 parent、recipe 或 incumbent 引用时保留，无引用后回收。
- 每 cert 状态索引、每 feature 固定 chart 网、cell broadphase、`connect_attempt_index`、`endpoint_checked`、pending vertices/edges、有限 `ConnectTask` 队列。
- `g,parent,parent_edge` 属 active SSSP；incumbent 是独立不可变完整路线快照和实际长度。

## 4. 区域发现与事务注册

区域扩展使用独立 `rng_expand`，首解前沿用原 A 的几何 gap、Projection/Steer、有限回缩和模型构造。Steer 返回新 cell、portal witness $w$ 及认证/slack 结果；`INSERT_CELL` 消费这些结果，只做数值一致性检查，不重复求 `max_margin`。

`INSERT_CELL(new_cell,parent,w,validation)`：

1. 暂存 cell、owner feature、pair feature 和 route 候选；$w\in D_{parent}\cap D_{new}$ 不成立则拒绝，不写全局索引。
2. 候选为 `parent.discovery_anchor`（root 用 source $s$）加 parent 证书空间索引中几何最近的 4 个 active finite-`g` 状态。按 anchor recipe 实际长度加距离，或 active 候选 $g(a)+d(a,w)$ 排序。
3. 依序尝试：anchor 直接共享 immutable recipe，即使未发布或 $g=\infty$；其他候选仅选中尝试时才沿 active parent 链建 prefix snapshot。source 用 $C_{parent}$ 端点例外；其他 $a,w$ 用缓存的 $D_{parent}$ membership。凭凸性算长边。保存首个可行候选的 `best_a,best_edge`；这是固定小候选启发式，不保证 top-4 中实际最短。通常 anchor 提供可行后备。
4. 预验证通过后原子提交 cell/feature/state。新 pair 建立唯一强制 anchor，`REGISTER_STATE` 只调用一次；写入 `PathRecord(prefix_ref, best_edge, total_cost)` 与 pending 长边。新 cell 失败不得留下半注册数据。
5. 读取注册时缓存的 $w\to G$ 边；若存在，以完整 `recipe + terminal_edge` 调 `TRY_INCUMBENT`。只到 $w$ 的前缀不是解。

既有 cell pair 仅由均匀样本同时通过两侧 slack membership，或原 Steer/已有 overlap 查询给 witness 时创建。默认不额外启动 overlap solver。$q$ 的两侧 validation token 就是 pair feature 的初始认证；先 `GET_OR_CREATE_FEATURE(i,j, chart=较小cell_id)`，再注册 q。

`REGISTER_STATE(pose,memberships,certs,tokens)` 先确认 token/version；每个新增 cert 标签只验证一次 slack，缓存结果。精确 intern 后只追加 membership、更新索引。新状态设 `g=∞, parent=NONE` 并进 pending vertices。每个新 membership/cert 创建一个 `ConnectTask(v,cert_id,r_task,vertex_id_cutoff,cursor)`，其中 `r_task` 和有限 cutoff 在创建时冻结；同时对新 cert 运行一次 endpoint 检查。`PROPOSE_FEATURE` 与 `INSERT_CELL` 不重复跑邻居/端点扫描。

## 5. 均匀细化与连接

细化用独立 `rng_refine`，$n$ 只计该流。默认 $k_0=7,n_k=2^k$，尺度为

$$
h_k=\gamma(\log n_k/n_k)^{1/3},\quad
\ell_k=\max(8,\log\log(n_k+e^e)),\quad
r_k=h_k\ell_k.
$$

取单调非增包络，默认禁止后续增大 $r$；充分大层有 $r\to0,h/r\to0$。每层冻结 cell ID snapshot 与有限 proposal 枚举；feature 网按新 $h_k$ 分片重建，未重建完的 feature 暂停 `PROPOSE_FEATURE` 并保存 cursor，新状态经 journal 合入。ordinary 与 anchor 网分开重建；普通代表始终 $h$-分离，proposal 可同时用两网拒绝近重复。

每个 uniform $q$ 用 broadphase/slack 对 snapshot cell 每个只求一次 membership token，得到 $S(q)=\{i:q\in D_i\}$。单 cell feature 提案；对所有无序 pair $(i,j)\subset S(q)$ 分片且不永久截断地 `GET_OR_CREATE_FEATURE` 并提案。$b=|S(q)|$ 时 pair 工作 $O(b^2)$，必须记录 $b$ 直方图。新状态/新 cert 的连接由 `ConnectTask` 立即排队。

`CONNECT_LOCAL(task)` 只在 task 的固定 `r_task`、cert version 与 vertex cutoff 内查询候选，使用 chart 距离和 `connect_attempt_index` 去重；通过共享 cert membership 与凸性建立不可变候选边。队列有 cursor，可分片续跑。新 membership 标签有自己的 task；不重新碰撞采样、不重算 slack、不改 active adjacency。

### 单调半径的连接覆盖

若 $u,v$ 最终共享 cert 且距离不超过当前 $r_k$，取较晚获得该 cert 标签的注册时刻 $t$。因 $r$ 不增，$r_t\ge r_k$；该注册创建的 task cutoff 包含较早状态，最终会枚举该边。exact-intern 上的多个新 cert 标签逐个注册，各自创建 task。故不需每层全图邻接重扫；若允许增大 $r$，该性质失效。

## 6. 循环和增量 Dijkstra

```text
MAIN:
    构造 C_root=C(start)，检查 valid 且 start∈C_root；失败返回
    注册 root owner feature；root.discovery_anchor=s，recipe 为空起点链
    s 是独立 endpoint；g[s]=0,g[G]=∞, parent 均 NONE
    active 空图已完成，active_exact=true，初始化 proposal 与 level 计数
    尝试 root 的直接 s->G；成功即 TRY_INCUMBENT，并将边留在 pending
    按 expand:refine:search = 1:1:2 轮转工作时片
    expand: 运行原 A 扩展；成功 cell 调 INSERT_CELL
    refine: 每 slot 提交一个 proposal 或续跑一个 cursor
    search: 续跑 PUBLISHING/INITIALIZING/DRAINING；满足批阈值则发布
    deadline/停止时返回 incumbent 与 unfinished；不额外强制昂贵 drain
```

时片约 1 ms 或一个不可分调用，是 soft budget。启动工作项前检查剩余 deadline；后端支持时设 time limit。不可中断调用可能超时，记录 `deadline_overrun`，不声称硬实时。expand/refine/search 的公平性和背压不得永久饿死有限任务。

批次阈值初值：新增状态 $\ge32$ 或边 $\ge128$ 或距发布 $\ge10$ ms；队列尾或有剩余预算的输出请求可发布小批。pending edge 高水位初值 100000，触发时暂停 expand/新 proposal，只 drain；不丢任务。

- `START_BATCH`: 上批排空后冻结 pending 集合和新 vertex；新顶点 `g=∞`。设 phase=PUBLISHING、`active_exact=false`，heap 空。
- PUBLISHING 分片把 batch 新边/降权不可变版本写入 active adjacency；全批边发布前禁止 heap pop。新边仍进下一 pending。保留旧 payload。全部发布后才开始初始化 relax cursor。
- INITIALIZING 分片对所有新增/降权有向边执行 `RELAX`，不 pop heap。全部完成后冻结该图，phase=DRAINING。PUBLISHING/INITIALIZING 期间只输出已有可行 incumbent/完整 discovery recipe。
- DRAINING 保持 active adjacency 不变。堆按 `(g,id)` decrease-key；`current_scan=(vertex,neighbor_cursor)` 未扫完前不能 pop 下一点。`RELAX(u,v,w)` 若严格改善，改 `g,parent,parent_edge` 并更新堆；$v=G$ 时检查 parent 路线。
- batch 完成 iff 初始化 cursor 完成、heap 空且 `current_scan=NONE`。否则即使 heap 暂空也不能完成。完成后最终检查 G 路线，phase=IDLE、`active_exact=true`。

边权严格正（目标零代价终端边允许），并行降权建新 immutable payload。搜索批内不更改 active 邻接/权重；旧 parent 与路线引用始终保留。浮点容差须报告为误差地板。默认排空 Dijkstra heap，不以 A* 提前停堆。

## 7. Incumbent 与存储

`TRY_INCUMBENT(PathRecord_to_G)` 先用持久链 `total_cost` 与 incumbent 比较；只有可能改善时才展平。检查从 $s$ 到 $G$ 的边 payload 引用、端点连续性、方向，并重算边长；保存独立快照。`UPDATE_INCUMBENT_FROM_TREE` 每次 G 有效 relax 和 batch 完成时沿 parent 链累计当前实际边长；不可仅因 `g[G]≥incumbent` 跳过，因为传播时 g 是上界。只有实际改善机会才展平。输出不做密集 collision recheck。

active parent、PathRecord、incumbent 对 edge payload 计引用；旧 incumbent/parent 替换时释放引用，无引用且不是 active 最小版本才回收。固定 cover 的 $M=O(Kn/\log n)$、$E=O(K^2n\ell^3/\log n)$ 是稀疏图界，不界定 recipe snapshot、历史 payload、pending task 总存储；需报告其实际峰值。

## 8. 理论边界和最小验证

固定有限 cover 下，若目标属于鲁棒可认证路径类、严格门户有正体积、均匀采样持续覆盖、$h/r\to0$、所有有限 ConnectTask 与增量 Dijkstra batch 最终完成，则近优有限链的代表扰动趋零，incumbent 条件性趋于该 cover 鲁棒类最优。source/goal 还需鲁棒端点连接条件。动态 cell 增长时该结论仍以每个已生成有限 feature 持续获得细化和公平任务完成为条件。有限回缩区域生成器未证明覆盖原始自由空间，因此不宣称全局 AO。

首版最小验证：每条边有 cert/chart/yaw witness；pair 状态双侧 D；start 的 C 例外不扩至 portal；自由 yaw 用 goal_yaw；坐标不随 rewire 移动；membership 只增；增量小图每批与 fresh Dijkstra 对照距离和路线 cost；PUBLISHING 禁止 pop、`current_scan` 未完不结束；recipe 共享前缀且 incumbent 端点完整；deadline 返回 unfinished。配对 A/ISCT benchmark 之后再做，wall-clock 计入区域、membership、任务、搜索和路线输出全成本。
